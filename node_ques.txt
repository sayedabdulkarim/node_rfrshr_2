19. What is event-driven programming in NodeJS?
    Answer:
    Event-driven programming = "Jab ye ho, tab wo kar"

    Code khud se nahi chalta, kisi event (action) ke hone ka wait karta hai, phir chalta hai.

    Examples:
    - Jab request aaye → response de
    - Jab button click ho → form submit kar
    - Jab message aaye → broadcast kar
    - Jab file read complete ho → data process kar

    Node.js pura event-driven hai - Express routes, Socket.io, file operations sab events pe kaam karte hain.

    Code Example:
    button.on('click', () => { });      // Click event
    socket.on('message', () => { });    // Message event
    app.get('/api', (req, res) => { }); // Request event

21. What is the difference between Access Token and Refresh Token?
    Answer:
    Access token is short-lived (15min-1hr) for API access. Refresh token is long-lived (7-30 days) to get new access token without re-login. This improves security - if access token is stolen, it expires quickly.

36. How to integrate google authentication?
    Answer:
    3 Steps:

    Step 1: Google Console Setup
    - Google Cloud Console → New Project
    - APIs & Services → Credentials → OAuth 2.0 Client ID
    - Client ID + Client Secret milega
    - Redirect URI: http://localhost:5001/api/auth/google/callback

    Step 2: Backend (Node.js)
    - npm install passport passport-google-oauth20
    - GoogleStrategy setup with clientID, clientSecret
    - Routes: /api/auth/google (login) + /api/auth/google/callback (redirect)
    - Callback me user create/find → JWT generate → frontend redirect

    Step 3: Frontend (React)
    - Button: <a href="http://localhost:5001/api/auth/google">Login with Google</a>
    - Token receive from URL params → localStorage me store

    Flow: Click button → Google login → Callback → JWT → Frontend → Done!

37. What is webSocket?

    Answer:
    WebSocket kya hai?
    - Real-time, two-way communication between client and server
    - Connection open rahta hai (persistent connection)

    Problem (Normal HTTP):
    - Client puchta rehta → "Kuch naya hai?" (polling - slow!)
    - Server khud se data nahi bhej sakta

    Solution (WebSocket):
    - Connection open rahta → Server khud bhej deta! (instant!)
    - Bidirectional: Client ↔ Server (both ways)

    Use cases:
    1. Chat apps (WhatsApp, Telegram)
    2. Live notifications (Facebook, Instagram)
    3. Live scores (Cricbuzz)
    4. Stock prices (Zerodha)
    5. Google Docs (real-time collaboration)
    6. Multiplayer games (PUBG)

    Real-time chahiye = WebSocket use karo!

62. If 100 users simultaneously try to resize images, should we use worker threads?
    What is Worker Pool and why is it needed?

    Answer:
    - YES, use worker threads BUT with Worker Pool (not unlimited workers!)

    Problem without Worker Pool:
    - Spawning 100 workers = 100 threads = 5-10 GB RAM = Server crash!
    - CPU overload (context switching overhead)

    Solution - Worker Pool:
    - Limit workers to CPU cores (e.g., 4-8 workers max)
    - Queue remaining requests (FIFO)
    - As workers finish, they pick next task from queue

    Benefits:
    ✅ Server stays responsive (non-blocking)
    ✅ Controlled resource usage (limited workers)
    ✅ All requests eventually processed (queued)
    ✅ No server crash or overload

    Implementation:
    - Manual: Create WorkerPool class with queue
    - Production: Use Bull Queue + Redis (persistent queue)

    Optimal Worker Pool Size = Number of CPU cores (or CPU cores × 2 for I/O tasks)

    Real-world: Instagram, YouTube use this pattern for image/video processing
