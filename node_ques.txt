1. How can we optimise express js performance?
   Answer:
   - Use gzip compression (compression middleware, jo server response ko compress karke bhejta hai (100KB → 30KB), reducing bandwidth aur faster page load.)
   - Enable caching (Redis, in-memory)
   - Use PM2 cluster mode (multi-core)
   - Optimize DB queries (indexes, lean())
     → lean() ONLY for READ, not for Edit/Delete/Create (returns plain JS object, no .save())
     → indexes = Sorted pointer list (like book index), instead of scanning all docs,
       directly jumps to data using algo called B-Tree (O(log n) vs O(n)) kind of binarySearch
   - Use async/await properly, avoid blocking code
     → Blocking (Avoid)              | Non-Blocking (Use)
       fs.readFileSync()             | await fs.promises.readFile()
       Heavy for loop (10L iter)     | Worker thread me daalo
       JSON.parse(hugeData)          | Stream use karo
   - Load balancing (Nginx)

2. Implement pagination with mongo db in nodejs ( with or without aggregation )
   Answer:
   // Without aggregation:
   const page = req.query.page || 1;
   const limit = 10;
   const skip = (page - 1) * limit;
   const users = await User.find().skip(skip).limit(limit);

   // With aggregation:
   await User.aggregate([
     { $skip: skip },
     { $limit: limit }
   ]);

4. Is nodejs single threaded?
   Answer:
   YES, but not really! Main thread (Event Loop) is single-threaded.
   BUT: libuv provides thread pool (4 threads default) for heavy I/O operations.
   So: JS code = single thread, I/O operations = multi-threaded behind scenes.

10. What is eventLoop in nodeJS?
    Answer:
    Event Loop = Watchman jo continuously check karta hai "kya kaam pending hai?"

    CODE:
    console.log('1');
    setTimeout(() => console.log('2'), 0);
    Promise.resolve().then(() => console.log('3'));
    process.nextTick(() => console.log('4'));
    console.log('5');

    EXECUTION FLOW:
    ─────────────────────────────────────────────────────────────
    Step 1: console.log('1') → Call Stack → Run → "1" print
    Step 2: setTimeout() → Callback Queue me daal diya
    Step 3: Promise.then() → Microtask Queue me daal diya
    Step 4: process.nextTick() → nextTick Queue me daal diya (HIGHEST priority!)
    Step 5: console.log('5') → Call Stack → Run → "5" print

    ★ Ab EVENT LOOP kaam shuru karta hai! ★

    Step 6: EVENT LOOP check → "Call Stack empty?"
            → YES → "nextTick Queue me kuch hai?" (Pehle check!)
            → YES → nextTick callback run → "4" print

    Step 7: EVENT LOOP check → "nextTick empty?"
            → YES → "Microtask Queue (Promise) me kuch hai?"
            → YES → Promise callback run → "3" print

    Step 8: EVENT LOOP check → "Microtask empty?"
            → YES → "Callback Queue (setTimeout) me kuch hai?"
            → YES → setTimeout callback run → "2" print

    OUTPUT: 1, 5, 4, 3, 2

    PRIORITY ORDER:
    ─────────────────────────────────────────────────────────────
    1. Sync code (console.log)     → Sabse pehle
    2. process.nextTick            → Microtask se bhi pehle!
    3. Promise.then (Microtask)    → setTimeout se pehle
    4. setTimeout/setImmediate     → Sabse baad

    EVENT LOOP KA KAAM:
    Loop {
      1. Call Stack empty hai? Nahi → wait karo
      2. Call Stack empty → Microtask Queue check → sab run karo
      3. Microtask empty → Callback Queue se ek uthao → Call Stack me daalo
      4. Repeat...
    }

    THREAD POOL (libuv) - Interview Answer
    ═══════════════════════════════════════════════════════════
    Q: Node single-threaded hai toh heavy kaam kaise hota hai?
    A: Thread Pool! (Default 4 workers background me)

    Kya jata hai Thread Pool me?
    → fs.readFile, fs.writeFile (file operations)
    → crypto.pbkdf2 (password hashing)
    → zlib (compression)
    → dns.lookup

    Kya NAHI jata? (OS handles directly)
    → http requests, TCP, network I/O

    Example:
    fs.readFile('a.txt')  → Thread 1
    fs.readFile('b.txt')  → Thread 2
    fs.readFile('c.txt')  → Thread 3
    fs.readFile('d.txt')  → Thread 4
    fs.readFile('e.txt')  → WAIT (queue me) jab tak koi free na ho

    Change pool size: UV_THREADPOOL_SIZE=8 node app.js

    Thread Pool vs Worker Threads (Q64):
    ─────────────────────────────────────────────────────────
    Thread Pool (libuv)     │  Worker Threads (worker_threads)
    ─────────────────────────────────────────────────────────
    Automatic               │  Manual create karna padta
    fs, crypto ke liye      │  CPU-heavy JS code ke liye
    Control nahi            │  Full control (tum banate ho)
    Default 4               │  Jitne chaho utne (but limit rakho!)
    ─────────────────────────────────────────────────────────

19. What are promises in nodeJs?

20. What is event-driven programming in NodeJS?
    Answer:
    Event-driven programming = "Jab ye ho, tab wo kar"

    Code khud se nahi chalta, kisi event (action) ke hone ka wait karta hai, phir chalta hai.

    Examples:
    - Jab request aaye → response de
    - Jab button click ho → form submit kar
    - Jab message aaye → broadcast kar
    - Jab file read complete ho → data process kar

    Node.js pura event-driven hai - Express routes, Socket.io, file operations sab events pe kaam karte hain.

    Code Example:
    button.on('click', () => { });      // Click event
    socket.on('message', () => { });    // Message event
    app.get('/api', (req, res) => { }); // Request event

    Node.js uses event-driven architecture where operations don't block the main thread. When an async operation like database query
    starts, Node registers a callback and moves on. When operation completes, an event fires and callback executes. This is managed by
    the Event Loop, making Node highly efficient for I/O-heavy applications.

21. What is buffer in nodeJS?
    Answer:

    Use: File read/write, network streams, image processing

    const buf = Buffer.from('Hello');  // String to buffer

22. What is the difference between Access Token and Refresh Token?
    Answer:
    Access token is short-lived (15min-1hr) for API access. Refresh token is long-lived (7-30 days) to get new access token without re-login. This improves security - if access token is stolen, it expires quickly.

23. What are streams in nodeJs?
    Answer:
    Stream = Data chunks me read/write karna (ek baar me nahi, thoda thoda)
    Types: Readable, Writable, Duplex (both), Transform (modify while passing)

    // 1GB file copy - Without stream (RAM full!):
    const data = fs.readFileSync('big.mp4');  // Pura RAM me load
    fs.writeFileSync('copy.mp4', data);

    // With stream (RAM safe):
    fs.createReadStream('big.mp4').pipe(fs.createWriteStream('copy.mp4'));

    Use: Large files, video streaming, real-time data

42. What is cluster in nodeJs?
    Answer:

    By default Node uses 1 core, cluster uses ALL cores

    const cluster = require('cluster');

    }

44. Can middleware work on both request and response?
    Answer:
    YES! Middleware ko req, res, aur next teeno milte hain.

    3 Types of Usage:

    1. Request pe kaam (Before route handler):
       const authMiddleware = (req, res, next) => {
         if (!req.headers.token) {
           return res.status(401).json({ error: 'No token!' });
         }
         next();
       };

    2. Response modify karna:
       app.use((req, res, next) => {
         res.setHeader('X-Powered-By', 'MyApp');
         next();
       });

    3. Response intercept (After route handler):
       app.use((req, res, next) => {
         const start = Date.now();
         res.on('finish', () => {
           console.log(`${req.method} ${req.url} - ${Date.now() - start}ms`);
         });
         next();
       });

    Examples:
    | Middleware | Works On                        |
    |------------|--------------------------------|
    | auth.js    | Request (token check)          |
    | cors       | Both (headers add karta)       |
    | morgan     | Both (request + response time) |
    | Error handler | Response (error format)     |

    Simple: Middleware = Gatekeeper for both incoming & outgoing traffic!

47. Explain Promise.all(), Promise.race(), Promise.allSettled()
    Answer:
    Promise.all([p1, p2, p3])
    → Sab complete hone ka wait, agar ek fail → sab fail

    Promise.race([p1, p2, p3])
    → Jo pehle complete ho (success ya fail), uska result

    Promise.allSettled([p1, p2, p3])
    → Sab ka wait, fail bhi track hota (koi reject nahi hota)
    → Returns: [{ status: 'fulfilled', value }, { status: 'rejected', reason }]

    Use: all = dependent tasks, race = timeout, allSettled = independent tasks

49. What are MongoDB indexes? Why are they important for performance?
    Answer:
    Index = Data ka shortcut (like book index) → Fast search

    Without index: Full collection scan (slow on 1M docs)
    With index: Direct lookup (fast!)

    db.users.createIndex({ email: 1 })      // Single field
    db.users.createIndex({ name: 1, age: -1 })  // Compound
    db.users.createIndex({ name: 'text' })   // Text search

    Downside: Slow writes (index update hota), more storage

50. Explain MongoDB aggregation pipeline with example
    Answer:
    Aggregation = Data transform/analyze karna (like SQL GROUP BY)

    // Get total orders per user:
    await Order.aggregate([
      { $match: { status: 'completed' } },           // Filter
      { $group: { _id: '$userId', total: { $sum: '$amount' } } },  // Group
      { $sort: { total: -1 } },                      // Sort
      { $limit: 10 }                                 // Top 10
    ]);

    Stages: $match, $group, $sort, $project, $lookup (join), $unwind

51. What is rate limiting? How to implement it in Express?
    Answer:
    Rate Limiting = Ek user kitni requests maar sakta hai, limit karna

    Problem: Bina limit → 1000 req/sec → Server crash / Brute force attack
    Solution: 100 req/min allowed, 101st pe → "Too many requests, ruk ja"

    Implementation:
    npm install express-rate-limit

    const rateLimit = require('express-rate-limit');
    const limiter = rateLimit({
      windowMs: 1 * 60 * 1000,  // 1 minute
      max: 100,                  // 100 requests allowed
      message: 'Too many requests, wait karo!'
    });
    app.use(limiter);

    Example: Login 5 attempts/15min, OTP 3/hour, API 100/day

53. How to prevent SQL injection and XSS attacks in Node.js?
    Answer:
    SQL Injection Prevention:
    - Use parameterized queries (NEVER string concatenation!)
    - Bad:  `SELECT * FROM users WHERE id = ${id}`
    - Good: `SELECT * FROM users WHERE id = ?`, [id]
    - Use ORM (Sequelize, Prisma) - auto-escapes

    XSS Prevention:
    - Sanitize user input: xss-clean, DOMPurify
    - Escape output: helmet middleware sets security headers
    - Use: app.use(helmet()); app.use(xss());

57. How to handle memory leaks in Node.js?
    Answer:
    Memory Leak = App memory use karta, release nahi karta → Server slow/crash

    Common Causes:
    - Global variables (garbage collect nahi hote)
    - Event listeners (remove nahi kiye)
    - Timers (clearInterval nahi kiya)

    Fix:
    - Event listener → socket.off() karo
    - Timer → clearInterval(timer) karo
    - Arrays → empty karo jab zarurat na ho

    Detect: node --inspect server.js (Chrome DevTools)

58. Explain MongoDB transactions with example
    Answer:
    Transaction = Multiple operations ek saath success ya fail
                  Beech me fail → Sab rollback (undo)

    Example - Money Transfer:
    const session = await mongoose.startSession();
    session.startTransaction();
    try {
      await Account.updateOne({ user: 'A' }, { $inc: { balance: -1000 } }, { session });
      await Account.updateOne({ user: 'B' }, { $inc: { balance: +1000 } }, { session });
      await session.commitTransaction();   // Success → Save
    } catch (error) {
      await session.abortTransaction();    // Fail → Rollback
    }

    Simple: "Ya toh sab hoga, ya kuch nahi hoga"
    Use: Money transfer, Order + Inventory update

59. What is soft delete? How to implement it?
    Answer:
    Hard Delete = Permanently delete (gone forever)
    Soft Delete = Delete nahi, bas "deleted" mark karo (recover ho sakta)

    Implementation:
    // Schema me add karo
    isDeleted: { type: Boolean, default: false }
    deletedAt: { type: Date, default: null }

    Simple: Recycle bin concept - galti se delete hua toh recover ho sake

62. How to optimize MongoDB queries? (indexing, lean(), select())
    Answer:
    1. Indexing: db.users.createIndex({ email: 1 })
       → Fast lookups on indexed fields

    2. lean(): User.find().lean()
       → Returns plain JS objects (not Mongoose docs) → 5x faster
       → Use lean() ONLY for READ, not for Edit/Delete/Create

       // ❌ Normal: Returns Mongoose Doc (heavy, with .save(), .populate())
       const users = await User.find({});

       // ✅ lean(): Returns Plain JS Object (light, no methods)
       const users = await User.find({}).lean();

    3. select(): User.find().select('name email')
       → Only fetch required fields → Less data transfer

    4. limit(): User.find().limit(10)
       → Don't fetch entire collection

    5. Compound indexes for multi-field queries
    6. Use explain() to analyze query: User.find().explain('executionStats')

64. If 100 users simultaneously try to resize images, should we use worker threads?
    What is Worker Pool and why is it needed?

    Answer:
    - YES, use worker threads BUT with Worker Pool (not unlimited workers!)

    Problem without Worker Pool:
    - Spawning 100 workers = 100 threads = 5-10 GB RAM = Server crash!
    - CPU overload (context switching overhead)

    Solution - Worker Pool:
    - Limit workers to CPU cores (e.g., 4-8 workers max)
    - Queue remaining requests (FIFO)
    - As workers finish, they pick next task from queue

    Benefits:
    ✅ Server stays responsive (non-blocking)
    ✅ Controlled resource usage (limited workers)
    ✅ All requests eventually processed (queued)
    ✅ No server crash or overload

    Implementation:
    - Manual: Create WorkerPool class with queue
    - Production: Use Bull Queue + Redis (persistent queue)

    Optimal Worker Pool Size = Number of CPU cores (or CPU cores × 2 for I/O tasks)

    Real-world: Instagram, YouTube use this pattern for image/video processing
